# 服务端加密存储 v0.8

## 目标

服务端加密存储用于降低数据库或文件存储泄露时的明文暴露风险。第一版重点覆盖新消息正文加密，旧消息迁移另做。

## 加密范围

- 消息正文加密。
- 附件元数据加密。
- 附件内容加密可选，取决于性能和备份恢复复杂度。

## 密钥来源

- 第一版：环境变量。
- 后续：KMS 或云厂商密钥管理服务。

密钥不得写入 git、文档、日志、聊天记录、前端代码或构建产物。

## 搜索能力影响

消息正文加密后，数据库层面无法直接进行全文搜索。后续可考虑：

- 只支持精确元数据搜索。
- 建立脱敏索引。
- 引入受控的搜索索引服务。

## 备份恢复影响

- 备份必须同时保留密文数据和密钥管理说明。
- 没有密钥时不能恢复明文。
- 恢复流程必须先确认密钥来源，再恢复数据库和附件。

## 迁移策略

- MVP：新消息写入时加密。
- 旧消息迁移作为单独任务。
- 迁移过程需要可中断、可重试、可审计。
- 迁移前必须备份。

## 性能影响

- 写入时增加加密开销。
- 读取时增加解密开销。
- 附件内容加密会显著增加上传、下载和备份恢复复杂度。

## 第一版 MVP

- 新消息正文加密。
- 解密只在服务端授权路径发生。
- 不改变前端显示行为。
- 旧消息迁移另做。
