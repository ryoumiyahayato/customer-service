# 服务端加密存储 v0.8

## 目标

服务端加密存储用于降低数据库或文件存储泄露时的明文暴露风险。第一版重点覆盖新消息正文加密，旧消息迁移另做。

## 加密范围

- 当前 MVP 已实现新消息正文加密。
- 当前 MVP 已实现附件展示文件名元数据加密。
- 当前不加密附件内容本体，附件内容加密属于后续增强。
- 当前不迁移旧数据，旧明文字段仍保留并兼容读取。

## 密钥来源

- 第一版：环境变量 `ENCRYPTION_KEY`。
- `ENCRYPTION_ENABLED=1` 时必须配置 `ENCRYPTION_KEY`。
- `ENCRYPTION_KEY_VERSION` 用于记录当前密钥版本，后续轮换和迁移需要依赖该标记。
- 后续：KMS 或云厂商密钥管理服务。

密钥不得写入 git、文档、日志、聊天记录、前端代码或构建产物。

## 搜索能力影响

消息正文加密后，数据库层面无法直接进行全文搜索。后续可考虑：

- 只支持精确元数据搜索。
- 建立脱敏索引。
- 引入受控的搜索索引服务。

## 备份恢复影响

- 备份必须同时保留密文数据和密钥管理说明。
- 没有密钥时不能恢复明文。
- 恢复流程必须先确认密钥来源，再恢复数据库和附件。
- 丢失 `ENCRYPTION_KEY` 会影响已加密消息正文和附件展示文件名的解密。

## 迁移策略

- MVP：新消息写入时加密。
- 旧消息迁移作为单独任务。
- 迁移过程需要可中断、可重试、可审计。
- 迁移前必须备份。

## 性能影响

- 写入时增加加密开销。
- 读取时增加解密开销。
- 附件内容加密会显著增加上传、下载和备份恢复复杂度。

## 第一版 MVP

- 新消息正文加密。
- 新附件展示文件名加密。
- 使用 Node 标准库 crypto 的 AES-256-GCM。
- 加密结果包含 ciphertext、iv、auth tag、algorithm 和 key version。
- 解密只在服务端授权路径发生。
- 不改变前端显示行为。
- 不加密附件内容本体。
- 不迁移旧数据，旧数据兼容读取。
- 旧消息迁移另做。
